# S2-7 Tennis Remote Scoring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Score tennis on the phone point by point, singles and doubles, in every format the organiser can set. The pad
shows the engine's call (0/15/30/40/AD, and raw counts in a breaker), the engine's serve side and the change of ends.
It records code violations up to game penalty, the game award, breaks and the set score, and it names every ending the
organiser records.

**Architecture:** A `tennis*` module set in `src/domain/scoring/` behind `ScoringSport`. `tennisFold.ts` is the
nested-kernel twin of `setBasedFold.ts` (ruling 224). It reuses the generic parts as they are: `streamOf`, `voidedIn`,
`voidsAgain` (`setBasedFold.ts`), `setBasedRefusalOf`, `envelopeOf`, `queuedEnvelopeOf`, `lineupOf`
(`setBasedEngine.ts`), `seatsOf`, `namesOf`, `sideOfEntrant`, `scoreText` (`setBasedSides.ts`), `standing`
(`setBasedEvents.ts`), `undoTarget`, `LedgerEntry` and `field` (`setBasedLedgerHistory.ts`). `foldSetBased` is not
generalised. The screen uses layout A (ruling 228) on `PadContent`/`PadSheets` with `ToolRow slots={4}`.

**Tech Stack:** Expo / React Native, TypeScript strict, vitest, `@seazn/engine` 7.0.0. Engine imports: `tennis` from
`@seazn/engine/sports/tennis`; `NestedState` and `serveContext` from `@seazn/engine/sports/nested`; `tennisPadRules`
from `@seazn/engine/pad`; `foldMatchWithStoppage` and `EngineError` from `@seazn/engine/core`; `foldEpochOf` from
`@seazn/engine/sport`.

**Spec:** `docs/specs/2026-11-12-s2-7-tennis-design.md` (approved 2026-11-12). Rulings 215–230 are cited by number;
read the spec's §3 table before any task. Research: `.superpowers/sdd/s2-7-research.md`. Lessons:
`.superpowers/sdd/s2-7-lessons.md`.

## Global Constraints

- **Engine and epoch.** Pinned `npm:@onryde/seazn-engine@7.0.0`, no bump (ruling 227). Tennis fold epoch **2**.
  Source reads it with `foldEpochOf('tennis')` and never writes the number; only `engineEpochs.test.ts` holds the
  literal `2`, copied by hand from the release.
- **What the phone never sends** (AGENTS §1; rulings 217, 218, 220): `core.forfeit`, `core.settle`, `core.abandon`, a
  sanction at level `default`; `server`, `scorer` or `meta` on `tennis.point`; `person`, `duration` or `at` on
  `tennis.interruption`; `reason` on a sanction or an award. `tennis.point` carries `{by}` only. Task 5 sweeps every
  tap kind for this.
- **No serve question** (ruling 216). `tossOf` always returns null. The serve ball shows the engine's `state.serving`,
  or nothing; never a phone guess.
- **The config.** The format is read from the cfg only, through `tennis.configSchema` and `tennisPadRules`. No source
  line names a variant or preset (7.0.0's cfg has no variant field). `tennisPadRules` members throw on an invalid cfg:
  wrap them as `volleyballFold.ts:60-66` (`decidingSetOf`) does.
- **Tool row** (ruling 228; volleyball F3): 4 cells that always fill the row, **Violation · Break · Award game · Set
  score** (ruling 231, the owner's). Set score is LAST and stays, `enabled: false`, once the set has a point (never
  removed, never an empty slot); Award game keeps its cell, disabled, in a breaker. No More tool. No cell changes width
  or label under the thumb. A label wider than its cell at 320 dp in any language takes a short form, with `said` the
  full word (ruling 232; volleyball's "T/O"): nl "Overtr." for "Overtreding", "Game geven" for Award game; the fit
  test decides the others.
- **Held picks.** Tennis holds no pick across taps. A sheet's answer goes with the tap that opened it. A sheet is
  dropped, with exactly one record line, when a score event lands from elsewhere while it is open (spec §9 lesson 4;
  volleyball F1).
- **Confirm steps.** The violation and award sheets end on a confirm step (lesson 8).
- **Copy.** en from the spec; es, fr and nl the controller's, in the same commit as en (`dictionaries.test.ts`). fr puts
  a no-break space before `?` and `:`. Numbers are not translated: "7–6(5)", "[10–7]" and 0/15/30/40 are the same in
  all four languages; "AD" is the engine's call, upper-cased.
- **Fit.** Every `scoring.tennis.*` key fits at **320 × 640 and 360** in en, es, fr and nl, with a metric as tight as
  the device. `padFit.test.ts` is 2007 lines, so the sweep lives in `src/ui/theme/tennisFit.test.ts`, as
  `volleyballFit.test.ts` does (AGENTS §3).
- **File size.** Every file under 500 lines (spec §6). Split `tennisPad.ts` and `tennisTools.ts` before 500.
- **Layering.** Generic files never import a tennis file. `SPORT_MODULES` gains `'**/*tennis*'`; `SPORT_OWN_FILES`
  gains `'**/*tennis*'` and `'**/*Tennis*'` (`*Tennis*` also matches `*TableTennis*`, sport-owned anyway). Check no
  generic file is caught.
- **Tokens only.** Card icon `cardCaution` for a warning, `cardDismissal` for a point or game penalty or a web default.
- **Tests.** Every new guard gets a named mutant and the test that kills it, listed in the task report (AGENTS §10). No
  expected value computed by the code under test: scores and calls from the spec or ITF rules, copy from the
  dictionary.
- **Orientation.** Portrait only; each task report says the orientation question does not apply. Screen tests run in
  en, fr and nl.

  recorded · the organiser ends the match". The phone still never sends the forfeit.
- **G2 (Task 8).** `FORFEIT_REASONS` (engine `core/types.js:68`) also has `withdrew`: it reads "Withdrew". A forfeit by
  `"both"` reads "Walkover".
- **G3 (Task 3).** `scoringMatch.base.test.ts:19` is a "table tennis" comment, not a sport key: nothing moves there. The
  other four tests in spec §6 move to `hockey`.
- **G4 (Task 11).** `SetScoreSheet` titles itself "Set score · Game {game}" and labels fields "Points — {side}"
  (`en.json:346-347`). Tennis needs "Set {n}", "Games — {side}" and "Tie-break — {side}": optional `title` and
  `fieldKey` props, a declared shared change against spec §6's "none planned". Badminton, table tennis and volleyball
  tests stay unchanged.

## Review Focus

1. **The tool row never moves.** At 0–0: Violation · Break · Award game · Set score. After the first point Set score's
   cell stays fourth, disabled, at full width. In a tie-break Award game is present and disabled. Pinned by `tennisTools.test.ts`
   (Task 6) and `TennisPadScreen.test.tsx` (Task 11, slot ids and widths).
2. **A sheet is open when a co-scorer's point lands.** The violation, award or set score sheet closes with one line and
   nothing is sent from it. Pinned by `useTennisMatch.test.tsx` (Task 9).
3. **No forbidden event or field.** A sweep over every `TennisTap` kind finds no forfeit, settle or abandon, no
   `default`, and none of `server`, `scorer`, `meta`, `person` on a break, `duration`, `at` or `reason`. Pinned by
   `tennisEvents.test.ts` (Task 5).
4. **Organiser endings are named.** Retired, Defaulted, Walkover, Withdrew and Abandoned show with their side on the
   strip, the result card and History, never "Drawn" or blank. Pinned by `tennisFold.test.ts` (Task 4) and
   `tennisHistory.test.ts`, `tennisSport.test.ts` (Task 8).
5. **The engine's call is read correctly.** Deuce versus Deciding point at 40–40, AD on the right side, raw counts in a
   tie-break, "Change ends" when `endsChanged` says so, result lines "7–6(5) 3–6 6–4" and "[10–7]". Pinned by
   `tennisFold.test.ts` (Task 4), `tennisPad.test.ts` (Task 6) and the replay (Task 10).
