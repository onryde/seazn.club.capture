# S2-5 Remote Scoring (football), the phone: Implementation Plan (Plan P)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A volunteer scans a football match's scoring code and scores it on the phone: a shared match clock, goals,
cards and substitutions with named players, the end of each period, extra time and a penalty shootout, into the same
ledger the web console writes.

**Architecture:** A fourth sport behind `ScoringSport` (S2 ruling 38): a `football*` module set in
`src/domain/scoring/` folding through `@seazn/engine/sports/football`, a pure clock (`footballClock.ts`) read against a
server-time offset the scoring port measures, its own hooks and screen. The kit gains parts that name no sport
(`ClockBar`, `TeamColumn`, `KickRow`, `ClockCorrectSheet`, a body slot in `PadContent`); `PadView` itself is unchanged.

**Tech Stack:** Expo SDK 57 / React Native 0.86.3 / Hermes; `@seazn/engine` = `@onryde/seazn-engine` 2.0.0 exact
(`football`, `FootballCfg`, `footballNextKicker`, `shootoutTally` from `./sports/football`; `footballPadRules` from
`./pad`; `foldMatch`, `foldMatchWithStoppage`, `EngineError`, `GameTime`, `compareGameTime` from `./core`;
`foldEpochOf` from `./sport`); vitest on react-native-web.

**Spec:** `docs/specs/2026-11-07-s2-5-football-design.md` (approved 2026-11-08, rulings 100–108), on top of
`docs/specs/2026-11-01-s2-remote-scoring-design.md` and S2-2's. Read both and `AGENTS.md`. The web half is Plan W
(`2026-11-08-s2-5-w-web.md`); this plan never edits it.

## What the recon found that changes the design (recorded here, told to the owner)

1. **Own goal payload is reversed in the design.** The engine's `by` on an own goal is the side whose player put it in,
   and the goal is credited to the other side (`football.ts:1255-1271`; golden `football.test.ts:276`, `{by: "H",
scorer: "H-p3", ownGoal: true}` credits A). Design §4's row and §6.3's `{by: <this column's team>, ...}` would be
   refused with a scorer and credit the wrong team without one. This plan: _Own goal_ in the column of the team
   **credited** records `{by: <the other team>, ownGoal: true, scorer?: <the other team's player>}`. Task 1 re-probes it.
2. **No `recorded_at` reaches the phone for its own events.** The web's 201 answer is `{seq, state_summary, outcome,
status, event_id, rules_version}` (web `server/usecases/scoring.ts:313-320`); the phone reads `{seq, event_id,
rules_version}` (`wire.ts:430-438`) and keeps an accepted tap as a stand-in whose `recordedAt` is the tap's own
   `createdAt` on the phone's clock (`sync.ts:396-406`), and the read cursor moves past it, so the server's row is never
   read. So: the offset comes from the HTTP `Date` header of every scoring answer (Task 3), and an anchor that is this
   phone's own stand-in or queued tap is counted on the phone's own clock (Task 5). Plan W may add `recorded_at` to the
   201 answer as a precision gain; nothing here needs it.
3. **"No slots → fold with no lineup" makes the ledger unfoldable** the moment another screen names a player: the
   engine throws on a scorer not on the pitch on replay too (`applyGoal` has no strict switch, `football.ts:1260-1267`),
   and the fold then answers `unfoldable: 'ledger'`. This plan: a side whose rows carry no `slot` (a web older than W)
   folds with **every row starting** (a superset, so named events from the console still fold) and is drawn
   team-only (§6.6); a side with no rows folds with no lineup.
4. **The `NON_MONOTONIC_TIME` resend is unreachable.** Every append carries `expected_seq`; a foreign event between the
   phone's read and its POST answers 409 `SEQ_CONFLICT` first, and the existing re-read, revalidate and
   `payloadForSend` restamp follow. A 422 `NON_MONOTONIC_TIME` can then only come from a ledger the phone already holds,
   where a resend is refused the same way: it is dropped as any refused tap (`scoring.dropped`, "Not recorded"). But
   the fold must judge queued taps **as restamped**, or `revalidate` drops an overtaken offline tap before
   `payloadForSend` ever runs (`scoringMatchState.ts:339`, `scoringMatchPump.ts:96-102`).
5. Engine facts the design pointed elsewhere for: `FOOTBALL_EVENT_SCHEMAS` is not exported by
   `@seazn/engine/sports/football` (its `index.ts` exports `football`, `FootballCfg`, `FootballEv`, five payload
   schemas, `footballNextKicker`, `shootoutTally`); use `football.eventSchemas`. The quarter names are not in
   `core/time.ts`: quarters reuse `H1` as Q1 and run `H1, Q2, Q3, Q4`, closed by `QT, HT, 3QT, FT`
   (`PERIOD_MARKER_PHASE`, `football.ts:755-759`; `playPhases`, `:880-887`). Period lengths are `phaseLengths`
   (`:958-975`, not exported), mirrored here. A second yellow needs a prior yellow and a yellow after one is refused
   (`:1300-1308`). The web's Correct floor is the design's (`clock.ts:313-329`, `adjustClock`: floor only in the same
   period).

## Review Focus

1. **An offline tap overtaken in the same period.** Clock running, phone offline, a goal tapped at H1 20:00 is queued;
   the console meanwhile records a card at H1 25:00. Back online the goal must go, stamped H1 25:00, not be dropped as
   illegal. Test: Task 6 `a queued goal below the ledger's newest stamp stays legal, raised to it`, and Task 7
   `payloadForSend raises a same-period stamp to the ledger's newest`.
2. **A sheet open across a period change.** The Goal sheet opens at H1 44:50; the console records Half-time before the
   scorer picks the player. The goal must not be stamped `{H2, 2690}`. Test: Task 7 `a stamp captured in another
period than the fold's is dropped`.
3. **A phone whose clock is five minutes wrong.** The console starts the clock; the phone shows the console's minute,
   and its own Start shows on the console at the same minute. Test: Task 5 `a server anchor reads through the offset`
   and `a device anchor ignores the offset`; Task 3 `the estimate converges inside 300 ms after five samples`.
4. **A team sheet with no `slot` (web older than W) and a console goal with a scorer.** The phone still folds and
   draws that team team-only. Test: Task 4 `rows with no slot fold as all starting`, Task 6 `a console goal naming a
player folds on a side with no slots`.
5. **Two changes at one stoppage under a window cap.** Two subs a minute apart in real time at the same stoppage
   share the fold's `asOf` and spend one window; a third window past `subWindows: 3` disables Sub with "No subs left".
   Test: Task 7 `two subs at one asOf share a stamp`, Task 6 `subsLeft is false once the window cap is spent`.

### Task 5: The clock, pure

**Files:** Create `src/domain/scoring/footballClock.ts` (+ test).

**Interfaces:**

- Produces:
  - `ClockAnchor = {period: string; elapsed: number; running: boolean; atMs: number; base: 'server' | 'device'}`.
  - `anchorOf(events: readonly AnchorEvent[], phase: string): ClockAnchor | null` where `AnchorEvent = {type: string;
payload: unknown; atMs: number; base: 'server' | 'device'; standing: boolean}` in stream order. The latest standing
    `football.clock` whose `at.period === phase`, after the last standing `football.period`. A clock event with no
    `at` re-anchors the previous same-period anchor projected to its `atMs`, taking its `running`; with none before it,
    it is skipped. Null: no clock event in this period (the clock reads 0, stopped, and stamps nothing).
  - `anchorBase(event: LedgerEvent, ownEventIds: readonly string[]): 'server' | 'device'`: `'device'` iff the id is
    own and `deviceLinkId === null` (the stand-in, recon fact 2); queued taps are `'device'` at `createdAt`.
  - `reading(anchor: ClockAnchor | null, now: {deviceMs: number; offsetMs: number}): number` (seconds): null anchor
    → 0; stopped → `elapsed`; running → `elapsed + max(0, floor((serverNow − anchorServerMs) / 1000))`, `serverNow =
deviceMs + offsetMs`, `anchorServerMs = base === 'server' ? atMs : atMs + offsetMs`.
  - `periodLengths(cfg: FootballCfg): Readonly<Record<string, number>>`: seconds, as the engine's `phaseLengths`
    (`football.ts:958-975`), the `periodSeconds` override applied only when the group's values differ.
  - `MatchTime = {kind: 'regular'; seconds: number; endMinute: number} | {kind: 'added'; endMinute: number;
overSeconds: number}`; `matchTime(at: GameTime, cfg: FootballCfg): MatchTime`: start offsets H1 0, H2/Q2 len(H1),
    Q3 +len(Q2), Q4 +len(Q3), ET_H1 the regulation sum, ET_H2 +len(ET_H1); `endMinute` = (start + len) / 60; `added`
    when `elapsed > len(period)`.
  - `clockText(t: MatchTime): string`: `regular` → `M:SS` (`0:00`, `7:05`, `45:00`, `125:30`); `added` →
    `{endMinute}+{M:SS of overSeconds}` (`45+0:01` at 45:01, `90+2:30` at 92:30; ruling 109), mirroring the web's
    `matchClock` vectors row for row.
  - `minuteText(t: MatchTime): string`, the scoresheet's "nth minute": `regular` → `{floor(seconds / 60) + 1}'`, and
    `{endMinute}+1'` when that passes `endMinute` (`41'` at 40:10, `45+1'` at 45:00); `added` →
    `{endMinute}+{floor(overSeconds / 60) + 1}'` (`90+3'` at 92:30).
  - `PHASE_ORDER: readonly string[]` = `['pre', ...footballPadRules.playPhases, 'SHOOTOUT']` (H2 and Q2 never meet
    in one cfg); `newestStamp(events: readonly {type: string; payload: unknown}[]): GameTime | null` (the last

    `captured` is null or `captured.period !== phase`; else `{period: phase, elapsed: max(captured.elapsed,
asOf.period === phase ? asOf.elapsed : 0)}` (design §7.3).
  - `subStamp(phase: string, asOf: GameTime | null): GameTime | null`: `asOf` when `asOf.period === phase`, else null.
  - `restamp(type: string, payload: unknown, floor: GameTime | null): unknown` (design §7.3, for a tap the ledger does
    not hold): no `at` or no floor → as is; `football.sub` → `at: floor` when `floor.period === at.period`, else `at`
    dropped; any other: same period and below → raised to `floor`; earlier period (by `PHASE_ORDER`) → `at` dropped;
    later or equal → as is; a period not in `PHASE_ORDER` → as is.
