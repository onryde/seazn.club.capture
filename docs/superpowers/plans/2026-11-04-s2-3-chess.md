# S2-3 Chess Remote Scoring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A scorer records one chess game's result (White won, Draw, Black won, with an optional How) on the phone, through a Chess pad over the shared Remote Scoring kit.

**Architecture:** One new sport module set, `chess*`, behind the `ScoringSport` port, keyed by the bootstrap's `sport_key` `boardgame`, shaped like `tableTennis*` but not set-based: the fold reads `@seazn/engine/sports/boardgame`'s state, a tap is `core.start`, `boardgame.result` or `boardgame.pairing`, and Undo is the existing `core.void`. One generic kit change lets a sport start without a serve pick.

**Tech Stack:** Expo / React Native, TypeScript strict, vitest, react-native-web (jsdom) for UI tests, `@onryde/seazn-engine` 2.0.0 (imported as `@seazn/engine`).

**Spec:** `docs/specs/2026-11-04-s2-3-chess-design.md` (rulings 57–61; the controller's calls in its §10). Read it and `AGENTS.md` first. Template to copy the shape of: `src/domain/scoring/tableTennis*.ts`, `src/hooks/useTableTennis*.ts`, `src/ui/screens/TableTennis*.tsx`.

## How it is executed (owner, 2026-11-04: "subdrivent sonnet for impl and review and opus for batch and whole review")

Subagent-driven. Per task: a Sonnet implementer, then a Sonnet reviewer; a fix round is re-checked by resuming the same reviewer. Batches: **A** = Tasks 1–2, **B** = Tasks 3–4. An Opus reviewer reads each batch's diff once, and one Opus reviewer reads the whole branch before the draft PR is marked ready. Task 5 is the controller's and the owner's, with no subagent. One implementer at a time. Every dispatch carries exact file paths, acceptance criteria, what not to touch, the verify command and an output cap (AGENTS.md §13).

## Global Constraints

- Engine `@onryde/seazn-engine` **2.0.0 exact** (ruling 53); the main checkout has 1.1.0 installed: in the new worktree reinstall with `NODE_AUTH_TOKEN=$(gh auth token) pnpm install` (never print the token) and confirm `node_modules/@seazn/engine/package.json` reads `2.0.0`.
- **No web change.** Forfeit, no-show, walkover, abandon and drawing lots are not sent from the phone (organiser-only on the web).
- Sport key `boardgame`; pad titled **Chess**, chess How words (ruling 61); i18n keys `scoring.chess.*` in `en`, `es`, `fr`, `nl` with identical keys and placeholders (`dictionaries.test.ts`).
- Domain files: `type` not `interface`, no `any`, no barrel files, `domain/` stays pure. Generic files never import a chess file (lint `SPORT_MODULES`).
- Styles through tokens only (`StyleSheet.create`, no colour literal); max 3 levels of JSX nesting; functions 10–25 lines; no snapshot tests; no `console.log`.
- WHITE and BLACK are words on chips, never colour alone. Result line text is numbers only: `1–0`, `½–½`, `0–1`.
- Nothing is sent before Record. `core.start {}` is required before a result (the engine accepts a result only in phase `live`).
- Checks: only touched files locally (`pnpm vitest run` on them with `--reporter=json --outputFile=<scratch>/r.json` and read `numTotalTests`; eslint and `pnpm prettier --check` on changed files; `pnpm tsc --noEmit`). Capture exit codes with a redirect, not a pipe. The full suite runs in draft-PR CI.
- Work in a fresh worktree (`git worktree add ../seazn.club.capture-worktrees/s2-3 -b feat/s2-3-chess origin/main`); `git stash` is shared, never use it; restore a mutation from a `cp` backup. Device builds only from a clean detached worktree, never the one JS is edited in; local Gradle + adb only; never `eas build`/`submit`/`update`. Commit per task; push and merge only on the owner's word.
- Every change answers the four questions (AGENTS.md §10): a second call, an empty input, an interruption, another orientation or language.

## Review Focus

Failure modes the spec implies that no single task's happy path exercises (each is pinned by a test in the named task):

1. A second tap on Record, or two before the first settles: exactly one `boardgame.result` (Task 3).
2. Another scorer records the result while this phone's sheet is open or queued: the sheet closes, the pad shows their result, Undo is hidden, the web's seq conflict reconciles as S2 does (Tasks 1, 3).
3. `cfg.colors` false: no chips, no Swap, buttons read "{name} won" (Tasks 1, 3).
4. The engine in phase `tiebreak` (a drawn bracket game): the waiting line shows and no result buttons (Tasks 1, 3).
5. A method that contradicts the outcome (a draw with `checkmate`) can never be built: the sheet lists only the outcome's own methods (Tasks 1, 3).
