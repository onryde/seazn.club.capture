## Findings

- **T12-F1** (fixed, Task 18): the doubles server's name replaced the Games count; it now sits under the side's name.
- **T12-F2** (fixed in engine 9.0.0): after an odd-games Set score the serve ball was hidden for the rest of the match. A
  tier-0 `tennis.set_summary` banked the set without advancing `state.serving` while the serve walk advanced, so
  `serveContext().serveOrderKnown` stayed false from then on (seen on the device in sets 2 and 3). The owner chose the
  engine fix ("Fix in engine now", 2026-11-13): engine #47 hands the serve on as the set played point by point would (odd
  games; a tie-break set always), tennis fold epoch 3 → 4, released as 9.0.0 (release #48); the app pins 9.0.0 and its
  tests now expect the server ITF Rule 10 gives (ruling F1's "no ball" stands only for an order the engine cannot name).
- **T12-F3** (fixed, Task 19, 78449e28): at 320 × 640 in nl a decided match's result card left the two final boards no
  room. A decided or ended match now scrolls the card and both halves, each at its own height.
- **T12-m1** (fixed, Task 18): a decided pad's halves read 0/0 with no result; ruling 239's final board replaced it.
- Minor copy (open): Set score's refusal says "a game in progress can't have that score" where it means the set; the long
  name on the serve button breaks mid-word ("Oberha/user-Lindqvist"); the shared "Another scorer since"
  (`scoring.pad.otherScorerSince`) reads unfinished under "Retired · {side}", on every sport (rewording offered).

## Changes for other sports

Each is generic, and the suites of the sports named run over it. None was declared in the design: §6 said "Generic
changes, declared: none planned", so every one below was found in the build.

- **`SetScoreSheet`** (G4): takes an optional `title` and `fieldKey`, defaulting to the shared words; volleyball and the
  other set-based pads run it.
- **`PadView`** gained optional fields: `result` (the carried-forward card's title), `PadHalf.server`, `scoreboard` and
  `finalBoard`. A sport that sets none of them draws as before; only tennis sets them.
- **The carried-forward card** (`PadStateCard`) takes an optional result title.
- **`ScoreHalf`** draws a natural-height half, only when `finalBoard` is set.
- **The queue hold** (Task 17), in the sync and the match reducer: `QueuedEvent.holdUntil` and `isHeld`; `nextSend` and
  `wakeAt` wait for a held head; `onTap(..., now)` and `background` release holds; the `amend` and `release` events; and
  `syncHold.ts` (`heldTapOf`, `amendQueued`, `releaseHeld`). Only a sport's `SportEvent.hold` sets one, and
  `releaseHeld` returns the same state when nothing is held, so no other sport saves any more than before.
- **`ScoringSport.sendNote`** and the runner's `noted` effect: a sport may say a line, logged at warn, when the head is
  sent with less than the scorer gave it (tennis: a point's chips dropped).
- **`SportFold.unfoldable.detail`** and `MatchView.unfoldable.detail`, and the `scoring.unfoldable` warn line in the
  generic `useScoringMatch` (`{reason, cause}`, the cause an engine code or an error's name, never a message).
- **`forgetScoringLink`** also deletes the match's switches (`forgetMatchSwitches`, `scoring.switch.*.{id}`) for every
  sport, and every caller of it reaches that.
- **Not changed:** the hub (`scoringHub.ts`). The toss is read as a serve-moving event in `tennisPointDetails.ts`
  (`tossIn`, `serveMark`), tennis's own file.
- **Lint:** `SPORT_MODULES` and `SPORT_OWN_FILES` gain tennis in both casings.
